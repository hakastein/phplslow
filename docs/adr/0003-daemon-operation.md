# Эксплуатация демона

Здесь решены первое построение базы, явное обновление её поколения и обработка повреждённого индекса.

## Первое поколение базы

Первое поколение базы демон строит сам, когда к ещё не проиндексированной базе подключается первый клиент.
Запросы ждут готовности. Явная команда обновления нужна только для следующих поколений.

Причина: первое подключение не требует отдельного ручного построения базы и не получает ответ по отсутствующему
индексу; последующие обновления базы остаются явными.

## Обновление базы

- Команда — `phplslow base update <путь-к-базе>`. Она подключается к демону базы или поднимает его, строит новое
  поколение и пишет ход в stderr.
- Код 0 означает, что новое поколение собрано и переключено. Оверлеи догоняют сами: команда не ждёт их готовности.
- Ненулевой код с причиной означает, что сборка не удалась; работает старое поколение.

Причина: обновление запускается явно, результат наблюдаем через код завершения, а неудачная сборка не лишает
клиентов рабочего поколения. Готовность оверлеев не задерживает результат обновления самой базы.

## Повреждённый индекс

Повреждённый файл поколения или оверлея удаляется, причина пишется в лог демона, файл перестраивается.
Запросы к нему ждут готовности. По повреждённому индексу сервер не отвечает. Копия «на разбор» не хранится.

Причина: ответы не должны опираться на повреждённый индекс; перестроение восстанавливает его, а отказ от копии
не расходует диск на повреждённые данные.

Реализация: DEV-14186 — общий демон на базу; DEV-14189 — обновление поколения базы; DEV-14190 — устойчивость индекса.
